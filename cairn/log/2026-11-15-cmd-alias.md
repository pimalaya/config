# `cmd` is the alias of `command`

Decision D6 of the CLI alignment round (the change cli-alignment-2026-11-15 in the pimalaya/.github cairn, task L6): `cmd` is accepted wherever a command is configured. In this crate `Secret` already carried `#[serde(alias = "cmd")]`; `CommandConfig` and its adapter read a value, never a key, and `notify` reads no command. The one gap was `sample::variants`, whose field rule paired a secret's `raw` with `command` alone: a sample offering `#password.cmd` beside an active `password.raw` built a variant holding both.

- src/sample.rs: `key` strips `.cmd` as it does `.raw` and `.command`. Test `a_secret_raw_command_and_cmd_are_one_field` fails on the old rule (the `cmd` variant keeps `a.raw` active).
- src/secret.rs: test `cmd_is_the_alias_of_command`, both keys read the command, written back as `command`.
- src/command.rs, src/lib.rs, README.md: the key is shown as `command` and the alias named.

carillon and comodoro, which refuse `cmd` in their own hooks today, accept it again on their side (tasks R3 and M1 of the round).

Capabilities moved: command (cairn/spec/command.md added, "`cmd` is the alias of `command`"); sample ("Each section is a base variant" modified, a scenario added).
